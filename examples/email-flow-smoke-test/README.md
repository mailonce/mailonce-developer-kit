# Email flow smoke test

A minimal Node.js CLI that sends a real test email through **your SMTP provider** to a MailOnce temporary inbox.

It does not use a private MailOnce API and does not require access to MailOnce infrastructure.

## What it tests

Choose one payload:

- `otp` — sends a six-digit one-time password
- `link` — sends a sample email-verification link
- `both` — sends both in the same message

This is useful for manually checking that your application's SMTP path can deliver a realistic verification email to a fresh temporary inbox.

## Requirements

- Node.js 20 or newer
- SMTP credentials you are allowed to use for testing
- a MailOnce temporary address created at https://mailonce.org

Do **not** use `mailonce.org` itself as the recipient domain. Use the temporary address generated by the MailOnce service.

## Setup

```bash
npm install
cp .env.example .env
```

Edit `.env` with your SMTP settings.

## Send a test

```bash
npm run send -- --to YOUR_MAILONCE_ADDRESS --type both
```

Examples:

```bash
npm run send -- --to abc123@YOUR_TEMP_DOMAIN --type otp
npm run send -- --to abc123@YOUR_TEMP_DOMAIN --type link
npm run send -- --to abc123@YOUR_TEMP_DOMAIN --type both
```

The CLI prints the generated OTP and/or verification URL so you know what you expect to receive.

## What to verify in MailOnce

After sending:

1. the message arrives in the expected inbox
2. sender and subject are correct
3. the OTP shown by your test matches the received message
4. the verification URL shown by your test matches the received message
5. your application's own email template still renders as expected if you adapt this example to use it

## Configuration

| Variable | Required | Purpose |
| --- | --- | --- |
| `SMTP_HOST` | yes | SMTP server hostname |
| `SMTP_PORT` | yes | SMTP server port |
| `SMTP_SECURE` | yes | `true` for implicit TLS, otherwise `false` |
| `SMTP_USER` | yes | SMTP username |
| `SMTP_PASS` | yes | SMTP password |
| `SMTP_FROM` | yes | sender shown in the test email |
| `VERIFICATION_BASE_URL` | link/both | base URL used to build the sample verification link |

## Safety notes

Use a dedicated development or staging SMTP account when possible. Never commit `.env`, SMTP passwords, production credentials, or real user data.
